# Architecture

`frontend/` is a Next.js JavaScript application. It calls an independent Flask REST API in `backend/`. NASA POWER historical/projection adapters, a NASA GIBS WMS image/legend proxy, and the deterministic rotation service are separate. The browser does not call NASA data endpoints directly. NASA responses use bounded, process-local TTL caches (daily values 6 h, scenarios 24 h, monthly profiles and GIBS maps/legends up to 7 days); caches clear on process restart and are not shared between deployment workers. Environment variables set API URL and CORS origins.

Current flow: a farmer can enter a global point, choose NASA GIBS layer/date/zoom, and register a field locally with a supplied GeoJSON polygon. The map overlays the point and boundary on the NASA WMS view; its point markers, area and overlay are not used to extract satellite values. `/api/climate` queries NASA POWER daily observations; `/api/climate/projection` fetches monthly ensemble climate scenarios; `/api/imagery` and `/api/imagery/legend` proxy GIBS maps and the layer's advertised official legend; `/api/rotations` validates inputs and ranks three rule-based sequences. GIBS science maps are displayed only and are not decoded into numeric model inputs. Printable field reports summarize the current browser analysis.

Field registration and report inputs are stored only in browser local storage, not in the database. Supabase authentication and feedback sync are available when the team configures a project; the expanded owner-scoped schema covers fields, boundaries, soils, crop profiles/history, NASA/weather observations, assessments, rotations, scenarios, zones, feedback, recommendations and reports. The SQL has not been applied to a live project. Public demo usage does not create shared farm records.
